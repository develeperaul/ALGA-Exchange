# История и рефералы — подключение GET

Дата: 30 октября 2026 года. Production: https://admin.aminexpay.com.

## Страницы и запросы

| Страница | Подключённые GET |
|---|---|
| `/orders` | `/api/transactions`, `/api/payouts/cash`, `/api/payouts/invoices`; выбор раздела, фильтры статусов, пагинация |
| `/orders/:id?kind=transactions` | `/api/transactions/{id}` |
| `/orders/:id?kind=cash` | `/api/payouts/cash/{id}` |
| `/orders/:id?kind=invoices` | `/api/payouts/invoices/{id}` |
| `/orders/history` | `/api/balance/history`; в переключателе доступны также заявки |
| `/referrals` | `/api/referrals/me`, `/api/referrals/commission`, `/api/referrals/profit`, `/api/balance` |
| `/referrals/my` | `/api/referrals/relations` |
| `/referrals/account` | `/api/referrals/me`, `/api/balance`, `/api/referrals/transactions` |
| `/referrals/account/history` | `/api/referrals/transactions`; по нажатию «Подробнее» — `/api/referrals/transactions/{uuid}` |

Чтение собственных списков/деталей требует авторизации, но не одобренного KYC. Гость на `/referrals` видит приглашение войти; остальные закрытые страницы защищены guard. При явном mock-режиме сохраняются прежние demo-страницы.

## Важные различия форматов

Документация на старом IP описывает общий баланс и поля repaid/debt. Фактический production `/api/referrals/me` уже отдаёт отдельные `attributes.balance` и `attributes.program`, но может не отдавать repaid/debt. Поддержаны оба формата: средства и условия реферальной программы берутся из вложенных данных при наличии. Непереданные показатели скрываются, нули не придумываются. Общий `/api/balance` используется как fallback и не прибавляется к реферальному балансу.

Default-настройка `/api/referrals/commission` не подменяет программу конкретного клиента из `/api/referrals/me`. Доход за период запрашивается с `filter[date_from]` и `filter[date_to]` после применения фильтра.

Код приглашения показывается и копируется как код. Сервер не передал каноническую ссылку приглашения, поэтому URL из домена приложения и произвольного query-параметра не строится.

В старых реферальных записях `currency=null` отображается как неизвестная валюта. Статус распределения награды и фактически зачисленная сумма различаются. `transactions_sum/count` приглашённых подписаны как сумма/число распределённых наград, а не оборот клиента.

Статус Transaction определяется числовым `status`, а не `completed_at`. Резерв и списание из резерва в денежной истории — отдельные события, их суммы не суммируются как два расхода. Суммы сохраняются десятичными строками без пересчёта через Number.

Реферальная история: production возвращает HTTP 422 на документированный `filter[type][]`. Поэтому загружается полный список страницами, а вкладки типа фильтруют уже загруженные записи локально. Кнопка «Показать ещё» остаётся доступна; отсутствие совпадений на загруженных страницах не объявляется отсутствием записей вообще. Параметр `type=0`, который сервер принимает без ошибки, не используется: на пустом аккаунте нельзя доказать, что он фильтрует. Фильтр периода дохода возвращает HTTP 200.

## Поведение загрузки

- Независимые блоки рефералов имеют собственные loading/error/retry: сбой профиля не превращает баланс в 0 и не скрывает успешный доход.
- Пустые списки отличаются от ошибок.
- Кэш — память текущей сессии, TTL 30 секунд; ручное обновление обходит кэш. При смене сессии данные очищаются, старые запросы отменяются/игнорируются.
- Пагинация использует только разрешённые query-параметры `links.next`, запрос всегда идёт на настроенный API origin. Bearer не отправляется на URL-хост из ответа.
- После смены серверного раздела/фильтра старые строки очищаются, запоздалые страницы не добавляются к новому списку. Локальные вкладки реферальной истории используют общий загруженный список.
- Форма создания реферального вывода и остальные финансовые POST этим подключением не реализуются. Доступные поля лимита/комиссии вывода из профиля можно прочитать, но `/referrals/account/withdraw` остаётся недоступным в API-режиме.

## Ручная проверка

1. Войти тестовым аккаунтом, открыть «Заявки» и переключить безналичные операции / наличные / инвойсы / движение средств.
2. Проверить пустые списки и ошибки; при наличии собственных записей открыть детали и следующую страницу.
3. Открыть «Рефералы»: сравнить код, баланс, программу и доход с ответами своего аккаунта. Не сохранять bearer или персональные данные в отчёте.
4. Открыть «Мои рефералы» и «История наград», проверить фильтр типа и детали собственной записи при её наличии.
5. Перейти между страницами, затем нажать «Обновить»: обновление должно отправить GET даже при наличии свежего кэша.
6. Выйти и войти другим разрешённым аккаунтом: предыдущие средства и списки не должны отображаться.

Для диагностики только структуры ответов есть `python3 docs/activity-api-probe.py`: скрытый ввод credentials, login и GET, вывод типов/имён полей без значений контактов/токена/сумм.

- Реферальный профиль, средства, программа, доход, список приглашённых и история загружаются; переключение вкладки начислений больше не вызывает 422.
