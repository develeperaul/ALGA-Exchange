# ALGA Exchange

Frontend на Vue 3, Quasar и Pinia. По умолчанию приложение использует API; локальный mock доступен только при явном выборе legacy demo режима.

## Режимы API

- Без `VITE_API_MODE=mock` используется API режим.
- `VITE_API_BASE_URL` задаёт origin или deployment root API, без завершающего `/api`. Например, `https://example.test`; запросы приложения добавляют пути `/api/...`.
- В dev сервере `/api` проксируется на `ALGA_DEV_API_TARGET`; если переменная не задана, используется `https://admin.aminexpay.com`. Production API origin — `https://admin.aminexpay.com` (без `/api`).
- Для локального legacy demo задайте `VITE_API_MODE=mock`. В этом режиме auth и demo данные обслуживаются локальными mock-адаптерами.

Не помещайте секреты в клиентские `VITE_*` переменные: они доступны браузерной сборке.

## Поддержка функций

В API режиме доступны вход, получение текущего профиля, регистрация и восстановление пароля через email-код. После установки пароля принимается новая сессия и загружается профиль. При сбое загрузки повторяется только запрос профиля, без повторной отправки пароля. Сессия хранится в `sessionStorage`, отдельно для API и mock режимов; серверные ответы и ошибки обрабатываются как JSON API.

Подтверждение регистрации хранит временное proof после успешной проверки кода, связывает его с email и сбрасывает при смене email. Пароль регистрации отправляется только после проверки кода.

Профиль различает гостя, загрузку, ошибку с повторной попыткой и авторизованного пользователя. Отображаются серверные email, телефон при наличии и статус верификации провайдера. Редактирование профиля API пока не предоставляет. Профиль загружается при входе/восстановлении сессии и хранится в памяти: переходы между страницами не вызывают повторный запрос. При возвращении в приложение после фонового режима данные обновляются без скрытия загруженного профиля. Перезагрузка приложения заново восстанавливает профиль с сервера, выход из аккаунта очищает кэш.

Подтверждение сброса пароля хранится только в памяти и сбрасывается при смене email, возврате, уходе со страницы и смене сессии. Устаревшие ответы не принимаются. Для отправки и проверки кода учитывается `Retry-After`.

Главная получает безналичные котировки публичным `GET /api/quotes` без суммы и токена авторизации. Покупка USDT доступна через СБП, продажа — на карту или через СБП; способы продажи доступны через выбор внутри таблицы. Серверный курс уже включает комиссию и задаётся в RUB за 1 USDT. Полная десятичная строка сохраняется в данных и подсказке; в компактной таблице число округляется до двух знаков только для отображения. Внутренние наличные курсы из `GET /api/rates` показаны отдельной строкой, только для внутреннего направления USDT → RUB; обратный курс не вычисляется.

Для курсов используется один существующий `HomeRateTable`: общий заголовок «Курс обменов (1 USDT)», колонки «Покупка» / «Продажа», строки «Безналичный» / «Наличный» и одна белая карточка по Figma. Состояния источников и повтор запроса встроены в строки; отдельные технические панели не добавляются.

Котировки не кэшируются в браузере, истёкшие значения скрываются, обновление выполняется вручную. Ошибка, загрузка и пустой список показаны отдельно для каждого источника; моковые цены и вымышленные стрелки изменения в API режиме не подставляются. Котировки и курсы не запускают финансовые операции.

В API режиме подключены onboarding KYC (`/kyc`), формы заявок наличного обмена (`/exchange/cash`) и инвойса (`/invoice`), а также форма транзакций (`/wallet`). Все POST отправляются только по нажатию пользователя. Наличные заявки и инвойсы требуют авторизации; создание транзакций — подтверждённого provider KYC. Принятие заявки не означает завершённую финансовую операцию. При неопределённом ответе транзакция повторяется только вручную с тем же Idempotency-Key и телом.

История `/orders` подключена к GET безналичных операций, наличных заявок и инвойсов с просмотром деталей. `/orders/history` показывает движения USDT-баланса. В `/referrals` доступны код приглашения, награды, баланс и условия программы; `/referrals/my` — приглашённые, `/referrals/account/history` — история реферальных записей с деталями. Данные кэшируются только в памяти текущей сессии на 30 секунд, «Обновить» загружает свежие данные; смена аккаунта очищает кэш. Production может возвращать отдельный реферальный баланс и персональные условия в `/api/referrals/me`: они приоритетны перед общим балансом и Default-комиссией. Отсутствующие показатели не заменяются нулями, валюту старых записей не предполагаем известной. Подробности — [docs/activity-api.md](docs/activity-api.md).

Старые deposit-маршруты, demo подтверждение наличного обмена и форма создания реферального вывода `/referrals/account/withdraw` остаются mock-only; в API режиме показывается страница недоступности.

## Разработка

```bash
npm install
npm run dev
npm run build
npm test
```

`npm test` запускает Vitest (`vitest run`); `npm run test:watch` запускает его в watch режиме.

## Структура

- `src/api/` — режим API, HTTP клиент, сессия и auth/KYC адаптеры.
- `src/stores/` — Pinia stores.
- `src/router/routes.ts` — маршруты; catch-all должен оставаться последним.
- Quasar router mode — `hash` в `quasar.config.ts`.
- Глобальные стили — `src/css/app.scss`; Tailwind utilities используют префикс `tw-`.
- SVG иконки подключены через `src/boot/init.js` и `vite-plugin-svg-icons`.
